# 一、结论先行

- **验证期(档①②)用网页 H5**:当天可上线、改完即生效、发链接就能找人试,验证效率最高。
- **正式运营(档③)主推原生 App**,小程序可作为获客/传播入口,但不适合做核心承载。
- **"自动读取微信聊天记录"在任何平台都不可行**(隐私红线),只能靠用户主动导出后上传/粘贴。验证期支持"粘贴 + 上传 txt"即可,门槛最低。

# 二、三种部署方式对比

| 维度 | 网页 H5 | 原生 App | 微信小程序 |
|---|---|---|---|
| 上线速度 | 当天~几天(最快) | 数周~数月 | 1~3 周 |
| ★ 导入聊天记录 | 手动上传/粘贴,本地解析,顺畅、隐私好 | 最灵活(可读文件、OCR 截图),但开发成本高 | 受限最多:微信禁止小程序读取微信聊天记录,只能手动粘贴 |
| 验证/迭代效率 | 最高,刷新即更新,无需审核 | 最低,每次更新要打包 + 商店审核 | 中,更新需微信审核 |
| 传播门槛 | 最低,点链接即用,无需下载 | 最高,要下载,内测还需 TestFlight 等 | 低,微信内扫码直达,易裂变 |
| 合规/上架门槛 | 内测期低(备案即可),正式运营仍需备案/资质 | 最高,苹果/安卓双审核,情感陪伴类易被重点审查 | 高且严,微信对"AI 仿真人/情感"类目审核严,易被拒/封 |

# 三、推荐路径(按阶段切换,不一条道走到黑)

- **档①②(验证期)→ 网页 H5**。当天上线、即改即生效、链接即可传播,验证效率碾压另两种。导入采用"用户手动导出聊天记录 → 上传/粘贴 → 本地解析",既快又隐私安全,正是现有 demo 的做法。
- **档③(正式运营)→ 原生 App 为主**,可选小程序做获客入口。App 对导入(读文件/OCR)与长期体验的掌控力最强。
- **小程序**:适合做轻量获客与传播裂变的入口,但因微信对情感仿真类审核严、且禁止读取微信记录,不适合做核心承载。

# 四、"快速导入聊天记录"的现实路径(关键认知)

没有任何平台允许 App/小程序"自动读取"用户的微信聊天记录——这是隐私红线,只能靠用户主动导出。现实可行的导入方式,按优先级:

1. **导出 txt 上传**:微信/QQ 自带"导出/迁移聊天记录",用户导出后上传文本文件。最干净、结构清晰,推荐为主路径。
2. **粘贴文本**:用户直接复制一段聊天粘贴进来。门槛最低,适合验证期。
3. **截图 OCR**:上传聊天截图,自动识别文字。体验好但需开发 OCR,留到档②③。

验证期(档①)只需支持"粘贴 + 上传 txt"即可,门槛最低、当天可用,demo 已实现。

# 五、隐私与合规设计(降低用户导入顾虑)

- **本地解析优先**:验证期坚持"聊天记录在用户浏览器本地解析,不上传原文到服务器",既降低合规风险,也更容易说服用户敢导入。
- **最小化与可删除**:只保留用于建立 TA 的必要信息,提供一键删除。
- **第三方权益提示**:提示用户仅使用自己合法持有的聊天记录,不得用于骚扰或损害对方(衔接阶段 9 的在世第三方风险)。

# 六、快速验证的具体落地建议(档①)

- 形态:一个单页网页(现有 demo 即可演进),部署到任意静态托管(国内需域名备案;验证期也可先用内网/临时链接对小范围熟人)。
- 导入:粘贴 + 上传 txt,纯前端本地解析(检索式匹配也在前端完成,无需后端)。
- 分发:把链接直接发给目标失恋人群朋友,无需下载安装。
- 迭代:根据反馈当天改、当天更新,几天内可迭代多版。

# 七、与整体节奏的衔接

本方案是开发节奏(档①②③)的"部署形态"落地版:验证期用网页换取速度与迭代,正式期用 App 换取体验与掌控,小程序按需做获客。导入方案则把"快速导入聊天记录"从设想落成可执行的三条现实路径。
