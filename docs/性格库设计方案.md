# 未尽 · 虚拟对象性格库设计方案

> 目标:为每个"虚拟对象"(前任/逝者/在世的人)建立一个性格库,让大模型基于稳定的人格设定来生成回应,而非每次临时猜。
> 测试版提供**两种性格库方案**(A/B)供用户选择,用之前的 👍/👎 评分数据对比哪种"更像 TA"。
> 建库方式:**引导问卷 + 自动提炼** 结合。问卷全部采用**心理学官方标准量表的选择题**。

---

## 一、总体设计

- 每个虚拟对象 = 一份性格库(JSON),存 `server/data/persona_<uid>.json`。
- 用户创建虚拟对象时,选择使用 **方案 A(结构化人格模型)** 或 **方案 B(叙事人设卡)**。
- 建库两步走:
  1. **引导问卷**(标准量表选择题)→ 立即生成初版档案,不依赖大量聊天记录。
  2. **自动提炼**(随聊天记录增多,大模型分析真实发言,更新/补全档案)。用户可随时手动改。
- 每次回忆模式调用,把该虚拟对象的性格库转成 system prompt 注入,模型据此"入戏"。

---

## 二、量表来源与合规

均为**学术公开、可自由使用**的标准量表,已核实:

| 量表 | 用途 | 题量 | 计分 | 版权 |
|---|---|---|---|---|
| **IPIP-50**(IPIP Big-Five Factor Markers, Goldberg 1992) | 大五人格 | 50(5维×10) | 1–5 李克特,含反向题 | **公开领域**,注明出处即可自由使用/商用 |
| **ECR-S**(Experiences in Close Relationships–Short, Wei et al. 2007) | 成人依恋 | 12(6焦虑+6回避) | 1–7 李克特,含反向题 | 学术公开,可用于研究 |

**他评改写说明**:标准量表原为"自评"(描述我自己)。本产品是用户**替虚拟对象作答**(他评/informant-report),学术上成立且有先例——只需把题目主语从"我/Am"改为"TA"。下方中文题目均已按他评改写。

> 引用出处(务必在产品内注明):
> - Goldberg, L. R. (1992). The development of markers for the Big-Five factor structure. *Psychological Assessment, 4*, 26–42. 题目来自 International Personality Item Pool (ipip.ori.org),公开领域。
> - Wei, M., Russell, D. W., Mallinckrodt, B., & Vogel, D. L. (2007). The Experiences in Close Relationship Scale (ECR)–Short Form. *Journal of Personality Assessment, 88*, 187–204.

## 三、方案 A:结构化人格模型(量化拆解派)

把人拆成可量化的心理学维度。学术性最强、反应逻辑最稳定可控。

### A.1 档案结构(JSON)

```json
{
  "schema": "A",
  "identity": {
    "name": "阿哲",
    "relation": "前任(恋人)",
    "calls_user": "傻瓜",
    "self_ref": "我"
  },
  "big_five": { "extraversion": 70, "agreeableness": 85, "conscientiousness": 45, "emotional_stability": 35, "intellect": 60 },
  "attachment": { "anxiety": 68, "avoidance": 30, "type": "焦虑型" },
  "values": ["陪伴", "被在乎", "自由"],
  "speech_style": { "tone": "温柔、爱撒娇、偶尔毒舌", "catchphrases": ["傻瓜","早点睡","记得喝热水"], "sentence_len": "短句为主", "emoji_habit": "爱用~和🌙" },
  "memories": ["说好放假去海边民宿", "总担心对方熬夜"],
  "boundaries": ["不假装自己还活着/没分手", "不做具体承诺(如'我明天来')"]
}
```

### A.2 问卷:IPIP-50(他评版,中文)

**指导语**:请根据你对「TA」的了解作答。想象 TA 平时的样子,判断每句话有多符合 TA。
选项:1 非常不符合 / 2 比较不符合 / 3 不确定 / 4 比较符合 / 5 非常符合。

> 每题后括号为**计分键**(维度+方向),仅供开发计分,**不显示给用户**。
> 维度编号:1=外向性 E,2=宜人性 A,3=尽责性 C,4=情绪稳定性 ES,5=才智/开放性 I。

1. TA 是聚会中的活跃分子。(1+)
2. TA 不太关心别人。(2−)
3. TA 总是有所准备。(3+)
4. TA 很容易感到压力大。(4−)
5. TA 词汇丰富、很会用词。(5+)
6. TA 话不多。(1−)
7. TA 对人感兴趣、爱关注别人。(2+)
8. TA 东西乱放。(3−)
9. TA 大部分时候都很放松。(4+)
10. TA 很难理解抽象的东西。(5−)
11. TA 和人相处时很自在。(1+)
12. TA 会说话伤人/损人。(2−)
13. TA 注意细节。(3+)
14. TA 常为一些事担心。(4−)
15. TA 想象力丰富。(5+)
16. TA 习惯待在人群边缘、不显眼。(1−)
17. TA 能体谅别人的感受。(2+)
18. TA 常把事情弄得一团糟。(3−)
19. TA 很少情绪低落。(4+)
20. TA 对抽象的东西不感兴趣。(5−)
21. TA 会主动开启话题。(1+)
22. TA 对别人的烦恼不太上心。(2−)
23. TA 会立刻把该做的事做完。(3+)
24. TA 很容易被打扰/心烦。(4−)
25. TA 常有很棒的点子。(5+)
26. TA 没什么话说。(1−)
27. TA 心肠很软。(2+)
28. TA 常忘记把东西放回原处。(3−)
29. TA 很容易生气/烦躁。(4−)
30. TA 想象力一般。(5−)
31. TA 在聚会上会和很多不同的人聊天。(1+)
32. TA 其实不太在意别人。(2−)
33. TA 喜欢有条理、有秩序。(3+)
34. TA 情绪起伏大、常变。(4−)
35. TA 理解事情很快。(5+)
36. TA 不喜欢引起别人注意。(1−)
37. TA 会为别人花时间。(2+)
38. TA 会逃避自己的责任。(3−)
39. TA 情绪常常大起大落。(4−)
40. TA 会用一些比较难的词。(5+)
41. TA 不介意成为焦点。(1+)
42. TA 能感受到别人的情绪。(2+)
43. TA 会按计划行事。(3+)
44. TA 很容易被激怒。(4−)
45. TA 喜欢花时间思考、反省。(5+)
46. TA 在陌生人面前很安静。(1−)
47. TA 能让人感到自在。(2+)
48. TA 对自己的事要求严格、一丝不苟。(3+)
49. TA 常常情绪低落。(4−)
50. TA 满脑子都是想法。(5+)

**计分**:每维度 10 题。反向题(−)先翻转:5→1,4→2,3→3,2→4,1→5;再对该维度 10 题求和(范围 10–50),可线性映射到 0–100 存入 `big_five`。
- 外向性 E:1+,6−,11+,16−,21+,26−,31+,36−,41+,46−
- 宜人性 A:2−,7+,12−,17+,22−,27+,32−,37+,42+,47+
- 尽责性 C:3+,8−,13+,18−,23+,28−,33+,38−,43+,48+
- 情绪稳定性 ES:4−,9+,14−,19+,24−,29−,34−,39−,44−,49−
- 才智/开放 I:5+,10−,15+,20−,25+,30−,35+,40+,45+,50+

### A.3 问卷:ECR-S 依恋(他评版,中文)

**指导语**:想象 TA 在亲密关系里的样子。选项 1 非常不同意 … 7 非常同意。
维度:AX=依恋焦虑,AV=依恋回避。R=反向计分。

1. TA 需要另一半反复保证"是被爱的"。(AX)
2. TA 有时会担心另一半没有自己那么在乎这段关系。(AX)
3. TA 想和另一半非常亲密,这有时会把对方吓到。(AX)
4. TA 担心自己会被抛弃。(AX)
5. 当另一半开始和 TA 变亲密时,TA 会想往后退。(AV)
6. TA 想和另一半亲近,但又总忍不住退缩。(AX)
7. TA 不太自在向另一半敞开心扉。(AV)
8. TA 更喜欢不要和另一半太过亲密。(AV)
9. TA 有心事时会转向另一半倾诉。(AV, R)
10. TA 会和另一半讨论自己的问题和担忧。(AV, R)
11. TA 很容易依赖另一半。(AV, R)
12. TA 觉得靠近另一半、依赖对方是件容易的事。(AV, R)

**计分**:R 题翻转(8-原分)。焦虑=题1,2,3,4,6求和;回避=题5,7,8,9R,10R,11R,12R求和。
- 判型(简化):焦虑高+回避低→**焦虑型**;焦虑低+回避高→**回避型**;两者皆高→**混乱型**;两者皆低→**安全型**。阈值取各维度中位数,可先用经验阈值(如 7分制均分≥4 为"高")。

> 注:ECR-S 原始为 12 题,上面第 3 与第 6 属焦虑相关表述,实际开发时以 Wei 2007 原表英文条目为准做最终校对(本文档中文为便于理解的他评改写,落地前建议核对官方英文条目逐条对应)。

### A.4 补充:非量表字段的采集

`identity / speech_style / memories / values / boundaries` 这些量表覆盖不到,用**少量直接选择/填空**采集:
- 称呼:"TA 平时怎么叫你?"(填空)
- 口头禅:"TA 最常挂在嘴边的话?"(填空,可多个)
- 语气(单选):温柔 / 毒舌 / 高冷 / 逗趣 / 沉稳 …
- 最难忘的事:(填空,可选)
- 这些也可由**自动提炼**从聊天记录补全。

## 四、方案 B:叙事人设卡(整体画像派)

不拆分数,用自然语言 + 真实片段整体刻画,像写角色小传。更生动、语感更强,依赖大模型发挥。

### B.1 档案结构(半结构化)

```json
{
  "schema": "B",
  "identity": { "name": "阿哲", "relation": "前任(恋人)", "calls_user": "傻瓜" },
  "one_liner": "一个嘴上毒舌、心里很软,总担心你熬夜的人",
  "sketch": "TA 表面大大咧咧,其实很敏感……在关系里容易患得患失,不擅长直接说爱,但会用行动关心你。",
  "golden_lines": ["傻瓜,这么晚还不睡", "早点睡,记得喝热水哦", "说好的,拉钩"],
  "scene_reactions": [
    { "when": "你说累了", "then": "先心疼,但嘴上说'谁让你不听话'" },
    { "when": "你提分手/离开", "then": "会先沉默,然后岔开话题,不愿正面谈" }
  ],
  "boundaries": ["不假装自己还活着/没分手", "不做具体承诺"]
}
```

### B.2 问卷(仍以选择题为主 + 少量开放)

**B 也先跑标准量表拿人格底色**,但可用精简量表减轻负担:
- 可选用 **TIPI-10**(Ten-Item Personality Inventory,Gosling 2003,公开)或直接复用 A 的 IPIP-50——取决于用户选"快速/深入"。B 主要用量表结果去**丰富叙事**,而非展示分数。

**B 特有:情景选择题(自编,基于心理学情景,抓"典型反应")。** 示例:

1. 当你说"今天好累",TA 最可能:
   A 立刻心疼地安慰你  B 嘴上嫌你不听话、心里担心  C 讲道理让你注意休息  D 沉默,不太回应
2. 你们吵架时,TA 通常:
   A 直接说出不满  B 冷战、不理人  C 先低头哄你  D 讲道理分析对错
3. 你提到"要不要分开/离开",TA 会:
   A 激烈挽留  B 沉默回避  C 假装没听见、岔开  D 冷静地跟你谈
4. TA 表达在乎的方式更偏向:
   A 直接说"我爱你/想你"  B 用行动(带吃的、提醒穿衣)  C 开玩笑/逗你  D 默默做,不说
5. TA 心情不好时:
   A 会主动找你倾诉  B 自己憋着不说  C 变得烦躁易怒  D 装没事

> 情景题的选项映射到叙事卡的 `scene_reactions` 与语气,自动生成 sketch。
> 金句库 `golden_lines` 必须是**原话**:让用户填几句 TA 的经典原话,或从聊天记录自动摘取。

## 五、建库流程(A/B 共用:问卷 + 自动提炼)

```
创建虚拟对象
  → 选择方案 A 或 B
  → [第一步] 引导问卷(标准量表选择题 + 少量填空/情景)
      → 计分 / 汇总 → 生成初版性格库 JSON,存 persona_<uid>.json
  → 开始使用(回忆模式注入该档案)
  → [第二步] 聊天记录积累到阈值(如 ≥100 条)
      → 触发"自动提炼":把 TA 的真实发言喂给大模型,输出/更新档案字段
      → 用户可在"档案编辑"页手动修改任意字段
```

- **第一步(问卷)**先做,不依赖记录,能立即用。
- **第二步(自动提炼)**随记录增多再上;它依赖聊天量,当前可暂缓(用户仍在积累记录)。
- 两步产出同一份 JSON,自动提炼只更新可推断的字段(big_five 分数、口头禅、金句、场景反应),不覆盖用户手动锁定的字段。

## 六、注入大模型的方式(让档案真正起作用)

每次回忆模式调用,把性格库转成 system prompt 片段,拼进现有 `llm.js` 的 system:

**方案 A 注入示例**:
> 你在模仿「阿哲」。TA 的人格画像:外向性偏高、宜人性很高、情绪稳定性偏低(容易敏感委屈)、尽责性中等;依恋类型为焦虑型(渴望亲近、害怕被抛弃)。TA 在乎"陪伴、被在乎"。说话温柔、爱撒娇、偶尔毒舌,常说"傻瓜""早点睡"。面对质问时更容易委屈退缩,而非强硬。红线:不假装自己还活着/没分手,不做具体承诺。

**方案 B 注入示例**:
> 你在扮演「阿哲」:一个嘴上毒舌、心里很软、总担心你熬夜的人。[sketch 全文]。TA 的经典口吻:"傻瓜,这么晚还不睡""早点睡,记得喝热水哦"。当对方说累了,TA 会先心疼但嘴上嫌;当对方提分手,TA 会沉默然后岔开。红线:同上。

两种都保留现有的 **RAG 检索**(附上 TA 真实说过的相关原话)+ **危机干预** + **"我是基于记忆的回声、非真人"的诚实底线**。

## 七、测试版 A/B 对比机制

- 创建虚拟对象时选 A 或 B(或对同一对象建两份档案切换)。
- 回忆模式回复沿用已做的 **👍 像 TA / 👎 不像** 评分,写入 `memory_log.jsonl`,字段追加 `schema: "A"|"B"` 与 `persona_version`。
- 攒够评分后,统计两种方案的好评率,客观判断哪种更像 TA、更适合继续。

---

## 八、开发优先级建议

1. **先做问卷 + 档案生成 + 注入**(A、B 两套,问卷用本文档题目),让功能跑起来。
2. 档案编辑页(手动改)。
3. 自动提炼(依赖聊天记录量,可稍后)。
4. A/B 评分对比统计。

---

## 九、伦理与准确性说明

- 量表用于"刻画语言风格与关系模式",不等于真正还原一个人的内心;产品内保留"这是基于记录/问卷的画像,非真人"的提示,与整体伦理设计一致。
- 他评改写、精简版、中文翻译均为工程适配;若用于对外正式发布,建议由心理学专业人士校对量表条目与阈值,并完整标注原始文献出处。
