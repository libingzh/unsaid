# 一、判断依据

用户的初版预期最看重两点:**体验"像不像 TA"** 与 **情绪慰藉是否有效**。这两点都是体验与验证问题,而非工程完整度问题。结论:**不应一上来就开发完整 App,而应采用"先验证、后建设"的渐进节奏**——把最贵的假设放到最便宜的阶段先验证,过了闸门才加大投入。

# 二、三档渐进节奏

## 档① 概念验证(第 1–2 周,几乎零成本)

用现有 HTML demo(可简单接一个大模型)给 10–20 个真实失恋朋友试用。验证目标:导入聊天记录后"像不像 TA"的概念到底成不成立。不做账号、支付、App,纯定性反馈。

## 档② 可真聊网页版(第 3–7 周,中等成本,重点阶段)

把 demo 接入真实大模型 + 真实导入解析 + RAG 人格还原,做成能真聊的网页版,不做 App、不上架、不做支付。招 50 人内测。验证目标:像不像 TA(打分 + 盲测)+ 情绪是否真的变好(量表)。**这是最匹配初版预期的阶段,核心验证都在这里完成。**

## 档③ 真实 App(第 8 周起,高成本)

只有前两档验证通过,才投入做真 App + 支付 + 完整安全机制 + ICP/算法备案 + 应用商店上架。备案耗时长,此时并行启动。

# 三、验证闸门(过不了就不往下烧钱)

## 闸门 1(档①→档②):概念成立吗?

- 试用者普遍反馈"有点那味儿/被触动"。
- 至少半数愿意继续聊下去。
- 不成立 → 调整人格还原方式,不要建网页版。

## 闸门 2(档②→档③):体验与慰藉达标吗?

- 像不像 TA 评分 ≥ 4/5;7 日留存 ≥ 25%。
- 情绪量表显示"用后变好"为主,且无二次伤害个案。
- 达标 → 才做真 App;不达标 → 在网页版继续打磨,不急于上 App。

# 四、为什么这个节奏最匹配初版预期

- 最看重的"像不像 TA + 慰藉有效"在档②网页版即可验证,无需先做完整 App。
- 把最贵的投入(App + 支付 + 备案)推迟到验证通过之后,假设不成立时损失最小。
- 每档 2–5 周、节奏短、可丢弃,每过一档证据更足,适合不熟悉技术、希望稳步推进的决策者。
- 现有 demo 正是档①的起点,可顺势演进到档②,前期工作不浪费。

# 五、内部迭代节奏建议

- 以"周"为单位:每周一个可试用的小版本 + 一次真实用户反馈,避免憋大招。
- 每档结束做一次"去/不去(go/no-go)"决策会,用闸门指标说话,而非凭感觉。
- 合规与安全不单独排进闸门,但全程在做:从档①即明示"AI 模拟",从档②即接入危机词兜底与基本内容审核。

# 六、与既有方案的衔接

- 本节奏是阶段 10(开发与测试)的执行节奏版:阶段 10 定义了"测什么、通过门槛是多少",本文档定义"按什么顺序和速度去测、何时加大投入"。
- 三档与阶段 10 的里程碑可对应:档①≈ 概念验证(早于 M0);档②≈ M1 核心体验 + 部分 M3 内测;档③≈ M0–M2 工程化 + 阶段 11 上线。
